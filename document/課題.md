1. **① 言語・REPLごとのモジュール実装**: 新言語向けに`launch`/`eval_template`/
   `Eval.Scan`/`field_drip`の4つと、自己申告の`Repl.Language`を作る（`repl-adapter-guide.md`）。候補4言語の
   チェックリストは下書き止まりで、実機では未検証
   - **scripts-mode で対象ファイルを安全に読み込む方法**も言語ごとに要る。Elixir は
     `SourceSanitize`（`defmodule`部分だけを抜き出して`-r`）で、エントリースクリプトの
     トップレベル副作用を避けている（§14.1）。他言語で同じ問題をどう避けるかは、4
     モジュールのどれにも含まれていない（guideの`source_sanitize.exs`の注）
   - **`embody`（§30）**: `Read`の無い値・無限構造・`Show`の無い値でもDBに入る形にする、
     対象プロジェクト側の固定モジュール。仕様は決まっていて、未実装。着手順は
     Clojure/Racket → Haskell → OCaml（Lisp系から始めると`repr`語彙の問題が見えないまま
     進む点に注意、§30.1）。Haskellで残っている未決・要実機確認は§30.5の5件:
     `exact`/`observe`/型表示の段をどう選ぶか（`-fdefer-type-errors`案が未検証）、IOを返す
     関数用の`observeIO`、`xipe embody`コマンド、exportされていない関数（`:load *Target`で
     回避できるか）、GHCiの出力バッファリングに実害があるか
2. **② ビルドツール吸収層 + `Evaluator`の言語dispatch配線**（§25）
   - 言語ごとのビルドツール優先順位表（例: `stack.yaml` > `*.cabal` > 裸の`ghci`）を、
     `Repl.Language`のcallbackとして自己申告させる（§25.4・§34）
   - Nix 環境: `flake.nix`がある対象は`nix print-dev-env --json`で環境変数を1回だけ
     解決し、flake の内容ハッシュでキャッシュする（§25.6）。**`shell.nix`だけの対象を
     どう扱うか**は§25.2で候補に挙がったまま、§25.6では扱われていない
   - `ready_pattern`をREPL自身の起動バナーではなく、固定の`XT_READY`マーカーにする（§25.3）
   - `Evaluator`の4オプション（`launch_module`等）を、`surface_table`の言語判定に応じて
     差し替える（いまはElixir固定）。①のモジュールが最低1つ無いと試せない
   - **`repl`/`build_tool`の置き場所**（§25.5・§29）: いまの「`surface_table`の全行に同じ値を
     複製する」形は仮のもの。ビルドツール判定を作るときに、`project.json`へ1個だけ持たせる
     案も含めて決め直す
3. **surface table を手で直すコマンド**（§34）: 2つ以上の言語が申告した拡張子（`.h`・`.pl`・
   `.cljc`など）や、拡張子の無いファイルは`language: nil`になる。これを利用者が行ごとに
   決めて書き込むコマンドを別途作る。単純な表への書き込みで、ほかの課題への依存は無い
   （crux）。決めること: 手で決めた値を`xipe table generate`の再生成でどう残すか
4. **保存された`table`を読む側へ切り替える**（§31）: `xipe table generate`で`table`は保存される
   ようになったが、`Project.find_sheets/1`・`Runner.launch_opts_for/2`は今も呼ばれるたびに
   その場で生成している。②のビルドツール判定・nix環境のキャッシュを載せるときに、保存
   された表を読む形へ切り替える
5. **`eval_table`の中身**（§24.1で命名のみ）: 評価結果を持つテーブルとして
   `tables/project/<id>/`に置く予定だった。`book.jsonl`の`calls`と役割が重なるので、
   要るかどうかから決める
6. **⑥ Scanner の言語非依存化**（§21.2〜§21.4・§25.1）: いまの Scanner は
   `Code.compile_quoted/2`に丸ごと依存していて、Elixir 以外は扱えない

## 2. サーバー（`xipe serve`）側

- **非同期`eval/run`**（§15・§28 E）: `Pipeline`の`"eval"`段が空スタブのまま。
  `xipe serve`経由では評価できない。決まっている方針: Evaluatorをプロジェクトごとの
  別プロセスにし、`pass_id`を即返し、`notify/rowChanged`で順次配信し、Bookの更新は
  `Serve.Project`へcastする。**同じプロジェクトの pass は直列に実行する**。
  **未決**: 直列なので、pass 実行中に来た次の要求を待たせるか拒否するか。`eval/cancel`
  を設けるか
- **`row/update`**: `eval/run`と同じく`Pipeline`経由。`"edit"`段（上記の二義を参照）の
  中身も未実装。編集そのもの（`Core.edit_args`/`set_prev`）は実装済み
- **WS側の複数ターン対話**（§17.3）: `InOut.run_to_completion/7`はCLI
  （`xipe dialogue depends`）でしか使われていない。`Serve.Socket`側の駆動ループが無い
- **`notify/*`の2ビットタグ**（§17.1）: `notify/*`にも`01`タグを持たせると決めたが、
  未実装。`Protocol.encode_notify/2`は素のJSON-RPC通知を出すだけで、直接応答に付く

- **`notify/*`への出自付与**（§17.1）: どのセッションの操作が引き金だったかを含めるか
  どうか。未決
- **CLIとサーバーの同時書き込み**（§2・§8.1）: 「サーバー稼働中はCLIもサーバー経由で
  書く」と決めたが、配線されていない。`serve_project_test.exs`の間欠フレークの原因で

- **`provider/*`・`provider/recheck`**（§9）: サーバー発リクエストの相関。tezcatl側の
  providerプロキシが無いと検証できない
- **`cell/complete`**: 値ベースの補完
- **`trace/*`**: `trace`/`run`テーブルのストレージ方式（ETSを併用するか）をv0.5で再検討

## 3. 評価（REPL往復）まわり

- **本当のハング時の経路が実機未確認**（§23.2）: BEAM が内部タイムアウトすら効かない
  ほど止まった場合の「固定デッドライン → `interrupt/1` → `kill/1`」は、安全に再現する
  方法が無く、フェイクの`Sender`によるユニットテストでしか確かめていない。
  **〔要判断〕** 検証課題として追い続けるか。あわせて、中断が効いたときに同じセッション
  で残りを続行する「option B」は見送ったまま
- **予期しない`XT_EXIT`**（§8.1）: `Scan.Direct.Iex.clean/1`は`exit_status`を検出するが、
  `Evaluator.wait_result/6`は読んでいない。セッションが途中で落ちても固定デッドライン
  まで待ち、`session_hung`と誤ったラベルが付く。安全側には倒れるので優先度は低い
- **PTY接続時のエコーバック**（§10.1）: PTY対応を足すときに、raw/エコー無効にするか、
  パーサー側で1回目を無視するかを決める。いまはplain pipeのみ
- **`eval.max_per_pass`・`compare`の誤差の設定化**（§5・§11.2・§28 C）: 設定ファイルの
  仕組み自体が無いので、モジュール属性で固定している
- **`:binding`参照の制約**（§22）: passごとにiexを起動し直すため、`:binding`
  （`Core.resolve_ref/4`のcatch-all）に落ちる参照は常に`skipped`になる。該当するのは、
  同じpassで先に評価されず、`exact`/`binary`の値も無く、`unsupported`かつpureとして
  呼び出し式を埋め込むこともできない参照先すべて。§22の実例`c_base`のように、
  **未分類でまだ一度も評価されていない参照先**もここに入る。制約として文書化する方針
  で決定済み。**`repl-adapter-guide.md`/仕様への明記が未実施**

## 4. Scanner・CLI

- **`defp`もnode化される**（§16.1）: `Scanner.extract_def_clauses/2`（`lib/scanner.exs:233`）
